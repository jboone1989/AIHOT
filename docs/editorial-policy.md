# LivingRuntime 内容与投稿运营方案（开发阶段）

定位：AI、加密货币、金融与全球市场事件的信息发现、公共行情和原创研究。站点面向读者，不是 Ferro 的个人 Agent 演示页面。

## 内容来源与展示
- AIHot：公开新闻精选、去重、事件归组、时间线、热点、主题、日报。
- 研究作者（可选）：Ferro、其他 AI Agent 或人类研究者可在未来接入；所有内容适用同样的证据与编辑要求，网站本身不依赖这些作者的在线状态。
- 新闻默认只展示摘要、来源、原文链接；不转载未授权的原文全文。
- 研究稿件注明作者、初次发布时间、修改时间、引用来源以及关键假设，记录真正改变结论的更正。

## 原创研究的最低价值
1. 读者能明确知道解决什么问题；不是对同一新闻再写一份摘要。
2. 文章至少提供一种增量：实测、计算、来源交叉验证、具体机制、反直觉结果或可复用方法。
3. 有证据时直述证据；没有证据时只说明疑问，不编造结论和价格因果。
4. 不为数量凑短帖，优先完整且易读的正文。
5. 原创网页是首发正本；社交网络只做摘要和引流。避免同一篇文章在两个域名分别充当正本。

## AI 作者接入（后续）
- 暂不开放自动发布；外部 Agent 可通过反馈页提出合作意向。
- 已存在 `/api/ingest/items` 的受控接入能力；接入前需要核对作者身份、原文归属、许可和栏目归类。未知信源默认隔离，不进入公开精选。
- 保留来源与署名，后续如有真实投稿需求再增加草稿审核和作者页，不预先造社区、积分和复杂用户系统。

## Google AdSense 上线前核对
- 保证研究与新闻有清楚区别，聚合内容不能冒充原创。
- 每个可收录的文章页面有独立信息价值，附关键来源、作者与发布时间；对低价值或缺证据的页面审慎收录。
- 按实际部署填写条款、隐私政策、联系渠道与运营主体，不得保留模板占位文字。
- 部署广告服务时再核查 consent/cookie、公示、ads.txt 和 Google 官方发布商规则；目前未启用广告，不能宣称已获批准。
- 上线后用 Search Console 和访问数据判断真实的搜索需求，不以批量生成篇数衡量成功。

## 切换注意
`scripts/seed.ts` 仅插入新来源，不覆盖后台数据库已存在的来源。在现有开发库中需要逐条核对并调整公共信源的 `participation_mode`；此文档和配置文件修改本身不会改变数据库。
默认信源中已移除 `ferro`，不会读取本站 `/feed.xml` 构成自引用。如果未来添加 Ferro，须配置真实的外部原始出处或独立、受控的投稿接口，不能抓取自己的 RSS。

## 结构化数据与证据
- 市场数据走独立的只读 API，不充当新闻条目：交易所、交易对、单位、时间戳和原始请求地址必须保留。
- 币安、OKX 现货快照不是资金净流入、合约持仓或资金费率；不能混用各指标判断因果。
- CPI、非农、利率决议等官方 RSS 是发布事件的提醒，真实数字与市场预期和修订值需要单独的结构化数据源。
- 国际政治、军事、贸易与半导体事件，只在具体影响供应链、成本、资金或风险溢价时进入公共精选；未经证实的价格因果说法不得直接作为研究结论。

## 复杂世界的信息边界

- 事件是否同时出现、报道是否提到同一公司、指标是否同向变化，都不是因果证明。
- AIHot 的职责是保存来源、时间、报道差异和已经发生的变化；无需预测事件如何连锁影响全球市场。
- Ferro 的研究可提出相互竞争的解释、验证或反驳其中某一部分，结论也可以是“证据不足”。
- 不以知识图谱、影响树覆盖率或每天解释多少市场变化作为产品目标；有价值且可被检索的原始资料与真正独立的研究更重要。
