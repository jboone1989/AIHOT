# NVIDIA capability-aware free prototype inventory and routing (EventGraph)

The NVIDIA `/v1/models` catalogue is refreshed at most once every two hours. **All returned model IDs are recorded**, partitioned into `text`, `vision`, `embedding`, `rerank`, `image`, `document`, `audio`, `safety` and `unknown` pools, with separate counts in the admin/pool overview. Unknown and specialized endpoints are never treated as chat endpoints solely because they appeared in the catalogue. Model IDs and provider metadata are hints, not compatibility proof.

Chat models are considered for editorial tasks only after a fresh real request. A worker runs at most **one probe per five-minute tick**; untested models are gradually examined rather than all 80+ on every cycle. Vision models are tested with an actual `image_url` input, and only image-proven models are eligible for vision tasks. Text models never replace a vision requirement. Recent production receipts (excluding probe receipts) supply stronger text evidence and two-hour failed/unknown receipt rates can trip a per-model circuit breaker. Every routed model must have a fresh successful check; no model is considered operational just because it appears in `/models`.

The specialized pools are **discoverable inventory**, not interchangeable executor endpoints. Existing `EMBEDDING_BASE_URL` / `EMBEDDING_MODEL` remains a fixed, separately configured embedding service: silently changing its model or dimensions mid-flight would corrupt recall vector compatibility. Image generation, audio, safety, OCR, and reranking need distinct task adapters, request/response validation, receipts and probes before any of those can be marked healthy or used in production. A catalog entry alone is not an enabled capability.

Production must explicitly set `MODEL_CALLS_ENABLED`, `NVIDIA_MODEL_POOL_ENABLED`, `NVIDIA_MODEL_DISCOVERY_PROBES_ENABLED` and provide `NVIDIA_API_KEY` + `NVIDIA_BASE_URL` when the pool is enabled. The production config contract fails if pool is on while model calls are disabled; see `scripts/production-env-check.py`. No paid-provider fallbacks or rate-limit bypass are allowed. Hosted NIM availability and free-prototype quotas vary.

Health evidence persists in PostgreSQL `settings[nvidia.model_pool.v1]` (schema evolved in place). Inspect without secrets: `node scripts/nvidia-pool.ts`; force one bounded check with `node scripts/nvidia-pool.ts --probe`. Worker queue: `cron.models.nvidia.probe`. Ferro's ChatGPT-only production routing is independent.

Generic editorial steps selecting `default` may opt into NVIDIA routing with `NVIDIA_POOL_ROUTE_DEFAULT=true`: plain-text steps use the text pool, steps declared `vision` use the vision pool. Explicit non-NVIDIA model choices are left intact. Graphiti's embedding model is independently fixed with `GRAPHITI_EMBEDDING_MODEL` and `GRAPHITI_EMBEDDING_DIM` (defaults `nvidia/nemotron-3-embed-1b`, 2048); changing either requires an intentional vector-index migration and must not be an automatic fallback.

A model that accepts both text and images is eligible for **text** routing after a valid text check, even if no image test has passed. It enters the **vision** routing pool only after a real image-input check. These are two independent permissions, not mutually exclusive classifications. The count displayed for vision measures verified image handling, not text health. Genuine HTTP 404s from NVIDIA hosted endpoints indicate models listed in the catalog but unavailable for that endpoint, and must not be marked healthy by relaxing JSON validation.
