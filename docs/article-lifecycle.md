# AIHot 普通资讯的生命周期（2026-10-14）

原则：明显广告、重复和领域无关信息应在采集入口的规则过滤、身份去重、日期过滤以及内容预筛阶段就被挡住，**不是**单独开一个“垃圾存储层”。有限资源优先服务有质量的新闻和研究。

## 7–30 天内：普通资讯正常使用

从本站首次发现时计时。每天定时处理一次，`NEWS_BODY_RETENTION_DAYS` 可设为整数 7–30，默认 **30 天**。

普通资讯仍可用原文、摘要、正文等材料参与当前报道核对和内容处理。公开列表按照自己的可见性和精选标准展示，并非所有抓取信息都会公开。

## 到期后：只保留可找回的轻量索引

普通、未精选、已处理完成的 RSS/web-list/json-list 新闻会压缩：保留文章 ID、标题、来源、URL、发布时间/发现时间、简短摘要、公开列表搜索文字、必要的材料内容哈希及归组关系。清除原始文章正文 HTML/文本、旧版本正文、全文搜索正文、全文翻译和不必要的原始采集 JSON / 媒体元数据；页面改为摘要加原文链接。对已有 externalId 的源保留该身份字段。

特例继续保存完整素材：已经精选（包括历史精选）、人工编辑过的材料，以及被事件综述引用过的报告。当前系统不会自动知道 Ferro 在外部是否收藏了某篇材料；若研究长期依赖该原文，研究证据应在 Ferro 自己的证据存储中维护引用和合规副本。

再次在 RSS 中遇见到期材料，不会将它重新归入重处理队列。Ferro 需要研究旧内容时先在 AIHot 的年度历史索引中检索出处，再独立访问原始发布者或做新的网络检索，不要求 AIHot 自动重采所有全文。

## 实施与资源边界

- 代码：`packages/backend/src/operations/news-compaction.ts`；迁移：`database/migrations/0086_article_compaction.sql`。已有每日定时清理任务复用此过程。
- 每次最多 2000 条，分 200 条/事务处理；不批量删除整篇文章及事件关系。
- 保留结构化分析历史和模型调用凭据的元数据，以便核账与修正判断。**本次没有清理模型 receipts 的请求/响应大字段**，后续依据真实数据库大小再单独处理，不能声称已实现数据库所有部分的完全瘦身。
- PostgreSQL 更新并不会立刻缩小数据库文件体积：需要自动 VACUUM 回收页供再次使用，磁盘用量须根据实际数据库表和索引统计监控。
- 这是开发分支代码实现，尚未对运行中的数据库执行迁移和实际压缩；生产上线前需使用测试数据库验证数据关系及历史搜索仍然可用。
